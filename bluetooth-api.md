## Сервис СКУД/AAA (auth)

AAA - Authentication, authorization, accounting.

**Service ID:** `f0`

### 1. Характеристика `status`

Текущее состояние AAA.

*   **Characteristic ID:** `01`
*   **UUID:** `f001`
*   **Свойства:** Read
*   **Тип данных:** `{global: u8, conn: u8}`

`global` - глобальный статус сервиса.  
`conn` - статус текущего соединения, валиден только при `global` == `AUTH_GLOBAL_STATUS__OK`.  

**Возможные значения `global`:**

*   `0`: `AUTH_GLOBAL_STATUS__DISABLED` - Устройство не поддерживает AAA в данный момент.
*   `1`: `AUTH_GLOBAL_STATUS__NOT_ACTIVATED` - Устройство не активировано, AAA невозможна, 
сначала необходимо провести процедуру активации.
*   `2`: `AUTH_GLOBAL_STATUS__OK` - Устройство готово к AAA, далее см. статус `conn`.

**Возможные значения `conn`:**

*   `0`: `AUTH_CONN_STATUS__WAIT_CERT` - Устройство готово к AAA, ожидается запись сертификата в `auth`.
*   `1`: `AUTH_CONN_STATUS__WAIT_IDENTITY_KEY` - Сертификат прошел проверку, но т.к. используется в первый раз, то 
необходимо установить ключ идентификации устройства, nokey ожидает его записи в `identity-key`.
*   `2`: `AUTH_CONN_STATUS__WAIT_IDENTITY_CHALLENGE` - Сертификат прошел проверку, 
nokey ожидает идентификации клиента (identity-challenge).
*   `3`: `AUTH_CONN_STATUS__PASSED` - AAA полностью успешно пройдена.

### 2. Характеристика `activate`

Активация устройства, доступна только при глобальном статусе `AUTH_GLOBAL_STATUS__NOT_ACTIVATED`.

*   **Characteristic ID:** `02`
*   **UUID:** `f002`
*   **Свойства:** WriteEnc
*   **Тип данных:** `PubKey`

В качестве данных передается публичный ключ, которым будет проверятся подпись сертификатов.  

### 3. Характеристика `auth`

Характеристика для начала AAA, в нее необходимо записать сертификат пользователя.  
Доступна только при статусе соединения `AUTH_CONN_STATUS__WAIT_CERT`.

*   **Characteristic ID:** `03`
*   **UUID:** `f003`
*   **Свойства:** WriteEnc
*   **Тип данных:** `{sign: u8[64], salt: u8[16], user_data: TLV}`

В качестве данных передается сертификат пользователя в бинарном виде. Его структура:  

| Смещение | Поле | Тип данных | Размер (байт) | Описание |
|---|---|---|---|---|
| 0 | `sign` | `u8[64]` | 64 | Подпись сертификата |
| 64 | `salt` | `u8[16]` | 16 | Случайное число (соль) |
| 80 | `user_data` | `TLV` | N | Данные пользователя в TLV формате |

**Список поддерживаемых TLV-тегов в user_data:**

| Tag ID (dec) | Имя параметра | Тип | Размер (байт) | Обязательный | Описание |
|---|---|---|---|---|---|
| 1 | `nokey_serial` | `String` | до 64 | Да | Серийный номер nokey, для которого сгенерирован сертификат |
| 2 | `user_name` | `String` | до 64 | Да | Имя пользователя |
| 3 | `privileges` | `Privileges` | 4 | Да | Маска прав пользователя |
| 4 | `create_datetime` | `DateTime` | 8 | Дата-время создания сертификата |
| 5 | `valid_from` | `DateTime` | 8 | Дата-время начала действия сертификата, если 0 - граница не определена |
| 6 | `valid_to` | `DateTime` | 8 | Дата-время окончания действия сертификата, если 0 - граница не определена |
| 7 | `valid_in_week_days` | u8` | 1 | Битовая маска дней недели, когда можно использовать сертификат, бит 0 - ПН, бит 1 - ВТ и т.д. Единица означает пригодность в этот день. |

### 4. Характеристика `identity-key`

Установка публичного ключа идентификации, используется для прохождения `identity-challenge`.  
Ключ возможно установить, только если он еще не был установлен для сертификата, используемого в данный момент.  
Доступна только при статусе соединения `AUTH_CONN_STATUS__WAIT_IDENTITY_KEY`.  

*   **Characteristic ID:** `04`
*   **UUID:** `f004`
*   **Свойства:** WriteEnc
*   **Тип данных:** `PubKey`

После записи ключа, для завершения AAA необходимо пройти `identity-challenge`.

### 5. Характеристика `identity-challenge`

Характеристика для подтверждения подлинности устройства.  
Иначе говоря, что устройство то же самое, что и использовало текущий сертификат первый раз.  
Доступна только при статусе соединения `AUTH_CONN_STATUS__WAIT_IDENTITY_CHALLENGE`.  

*   **Characteristic ID:** `05`
*   **UUID:** `f005`
*   **Свойства:** ReadEnc, WriteEnc
*   **Тип данных (чтение):** `u8[16]`
*   **Тип данных (запись):** `u8[64]`

Для прохождения идентификации необходимо:
- Прочитать данную характеристику.
- Подписать прочитанные данные приватным ключем идентификации(который был сделан для установки `identity-key`).
- Записать подпись в данную характеристику.

После этого AAA будет пройдена.  
Статус(`status`) должен будет поменяться на `AUTH_STATUS__PASSED`.  

### 6. Характеристика `used-certs`

Получение сертификатов использовавшихся за все время (включая отведенные).  

*   **Characteristic ID:** `06`
*   **UUID:** `f006`
*   **Свойства:** ReadEnc, WriteEnc
*   **Права:** `OPEN_DOOR_HISTORY`
*   **Тип данных(чтение):** `{salt: u8[16], user_data: TLV}`
*   **Тип данных(запись):** `u16`

TLV теги такие же как и в характеристике `auth` + дополнительные:  

| Tag ID (dec) | Имя параметра | Тип | Размер (байт) | Обязательный | Описание |
|---|---|---|---|---|---|
| 16 | `last_use` | `DateTime` | 8 | Да | Дата-время последнего применения сертификата (с точностью до суток) |
| 17 | `valid_state` | `enum ValidState` | 1 | Да | Состояние сертификата. |

Возможные значения для `enum ValidState`:
*   `0`: Не валидный, был отведен вручную (характеристика `revoke-cert`).
*   `1`: Валидный.
*   `2`: Валидный, но для старого ключа, скоро может быть удален (характеристика `remove-old-master-key`).

Чтение характеристики возвращает набор данных только для одного сертификата.  
Чтобы прочитать несколько, необходимо несколько раз подряд прочитать характеристику, 
каждый раз будет возвращаться следующий сертификат.  
Т.е. работает авто-инкремент указателя.  
Запись в характеристику управляет указателем.  

Чтобы прочитать все сертификаты с 0-го, необходимо:
* Записать 0.
* Считывать сертификаты пока не будет получен отказ (`INVALID_OFFSET`).

Чтобы прочитать конкретный сертификат (напр. 123), необходимо:
* Записать 123.
* Считать сертификат.

### 7. Характеристика `revoke-cert`

Отозвать/отвести сертификат.  

*   **Characteristic ID:** `07`
*   **UUID:** `f007`
*   **Свойства:** WriteEnc
*   **Права:** `CERT_MANAGE`
*   **Тип данных:** `u8[16]`

В качестве данных записывается `salt`, нужного сертификата.

### 8. Характеристика `rotate-master-key`

Заменить публичный мастер-ключ, которым nokey проверяет сертификаты.  
При этом старый будет сохранен(перемещен во второй слот) - сертификаты со старым ключем будут приниматься.  
Отведенные сертификаты старого ключа будут удалены.  

Для полного перехода на новый ключ(завершение ротации) см. характеристику `remove-old-master-key`.  
В случае если предыдущая ротация не завершена(второй слот не свободен), то будет ошибка.  

*   **Characteristic ID:** `08`
*   **UUID:** `f008`
*   **Свойства:** WriteEnc
*   **Права:** `ROTATE_MASTER_KEY`
*   **Тип данных:** `PubKey`

В качестве данных передается новый публичный ключ, которым будут проверяться новые сертификаты.  

### 9. Характеристика `remove-old-master-key`

Завершение ротации - полный переход на новый ключ, удаление старого.  
При этом все сертификаты со старым ключем будет БЕЗВОЗВРАТНО удалены.  

*   **Characteristic ID:** `09`
*   **UUID:** `f009`
*   **Свойства:** Write
*   **Права:** `ROTATE_MASTER_KEY`
*   **Тип данных:** `u8`

Для выполнения необходимо записать `1`, другие значения не принимаются.  

### 10. Характеристика `reset`

Характеристика для сброса активации устройства.  

*   **Characteristic ID:** `0A`
*   **UUID:** `f00A`
*   **Свойства:** Write
*   **Права:** `RESET_AUTH`
*   **Тип данных (запись):** `u8`

Для сброса активации необходимо записать `1`.  

После этого активация устройства будет сброшена - публичный `MasterKey` удален, все сертификаты удалены, настройки устройства при этом не сбрасываются.  
Статус(`status`) должен будет поменяться на `AUTH_STATUS__NOT_ACTIVATED`.
